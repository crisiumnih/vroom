# Bank-address and cache-port implementation

This follow-up replaces the oversized bank selectors identified in the
[first baseline](baseline-20261009.md). It preserves 32-bit payloads, FP32
operation ordering, handshakes, and protocol latency. It does not implement
the external floating-point operators or establish the 10 kHz inference deadline.

## Implemented changes

- Each physical bank derives its local read/write address from the vector's
  starting row and whether that bank wraps to the next group of sixteen.
  Bounded unsigned addresses replace signed integer arithmetic and dynamic
  writes into packed address buses.
- A shared four-stage rotation network routes sixteen bank words to lanes;
  reverse rotation routes retired results and masks to banks. Progress metadata
  travels with its accumulator. The network is combinational.
- Tile bounds use a shared 11-bit `allocated_words - read_base` subtraction.
  Underflow is retained; enabled lanes outside the allocation still fault, while
  mask holes and a completely masked request remain valid.
- Pinned-cache boot writes explicitly share port A's address with inference
  reads. The sealed/unsealed phases are exclusive, so the mapper can use two
  physical ports without replicating the 176 KiB payload.

The address equations, units, range assumptions, and interface limits are in
[the memory description](../README.md) and [dense executor contract](../dense-engine.md).

## Functional evidence

The complete seed-2805 regression passes: 12/16 lanes, 3/19-cycle simulated
FP32 operators, both cache read ports, rate monitoring, strict Verilator lint,
and generic Yosys structural checks. All 772 original numerical output records
and all original command-cycle records are identical to the saved baseline in
each of the four dense configurations.

Added tests check 2,048 tile-window reads per lane configuration, including
every base address, sparse masks, short allocations, and physical-end overflow.
Each dense configuration additionally computes 1,024 scalar MACs and 256 distinct
outputs using every accumulator-bank alignment, reads 512 dense/sparse result
windows, and checks result-address overflow. Total distinct checked dense output
records are 1,028 per configuration; window rereads are counted separately.

This is functional simulation evidence with synthetic finite inputs and a C/VPI
FP32 operator. It is not a checkpoint parity test or hardware measurement.
The original nominal-100-MHz command-cycle sums remain unchanged: 13,131 / 10,452
cycles for 12/16 lanes at operator latency 3, and 23,794 / 22,606 at latency 19.
Even these sums exclude initialization, some DMA/dispatch, nonlinear functions,
and controller integration, and already exceed the inner 10,000-cycle budget.

## Routed timing and failures

Apio 1.6.0 supplies openxc7 2026.09.24, nextpnr-xilinx `0eae9fb` and the same
chip database used by the baseline. Clock constraint: 100 MHz / 10 ns.

| Probe | Seed | Routed Fmax | Outcome |
| --- | ---: | ---: | --- |
| Cache | 2805 | 185.19 MHz | Meets the diagnostic 100 MHz constraint |
| One tile, 16 lanes | 2805 | 66.22 MHz | Fails 100 MHz; baseline was 22.35 MHz |
| Dense core, 12 lanes | 2805 | Unavailable | Backend cannot route one constant-ground sink |
| Dense core, 12 lanes | 2806 | 34.74 MHz | Routes with all constant sinks connected; fails 100 MHz |
| Dense core, 16 lanes | 2805 | Unavailable | Backend cannot route 65 constant-ground sinks |

The constant-connectivity failures are retained as failed runs. The backend's
suggested `--allow-const-holdouts` bypass was not used: it explicitly warns that
the resulting bitstream would be wrong. Seed 2806 is an independently recorded
retry, not a replacement for seed 2805 or evidence of robust timing closure.
The preliminary pre-route estimate is not substituted for routed Fmax.

The routed 12-lane critical path is `issue_row[0]` through selected-row arithmetic,
bank addressing, column-progress RAM, rotation/check logic, and `state[0]`.
It totals approximately 28.8 ns: 3.7 ns logic and 25.1 ns routing. The single-tile
critical path goes through read-range validation into sequential control,
approximately 15.1 ns. The memory/validation/state path needs architectural
separation or pipelining and fresh verification; that is proposed follow-up work.
No false-path exception or relaxed clock constraint has been used to hide it.

The chip database still maps the nominal 35T to a larger 50T fabric and reports
75 BRAM36 / 120 DSP sites versus the 35T's 50 / 90. These frequencies are
**open-backend diagnostics, not Arty A7-35T timing sign-off**. The reductions do
not prove complete device fit. FP32 operators, DDR/MIG/CDC, nonlinear functions,
resident W0/W2, cache-to-engine routing and controller scheduling are excluded.
The current design still fails the requested clock and inner-loop budget.
