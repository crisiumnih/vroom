# First open-flow baseline: fails fit and timing

On 2026-10-09, the existing RTL was mapped with Yosys 0.63 and placed/routed with
Apio-provided nextpnr-xilinx revision `0eae9fb`. Target frequency: 100 MHz; seed:
2805. Apio Python package: 1.6.0; openxc7 package: 2026-09-24. The design RTL was
not changed during the probes. Arithmetic is still an external FP32 interface.

| Probe | Mapped LUT1–6 cells | LUT6 cells alone | DSP48E1 | RAMB36 | Result |
| --- | ---: | ---: | ---: | ---: | --- |
| Dense core, 12 lanes | 62,614 | 23,719 | 59 | 0 | Placement fails: LUT region overflow |
| Dense core, 16 lanes | 82,632 | 30,745 | 79 | 0 | Placement fails: no LUT sites remain |
| Pinned cache | 799 | 6 | 0 | 88 | Placement fails: no BRAM sites remain |
| One tile buffer, 16 lanes | 7,517 | 3,779 | 15 | 0 | Routes; backend Fmax 22.35 MHz, fails 100 MHz |

Both core probes additionally use one RAMB18. LUT1–6 counts exclude distributed
RAM and are not post-pack physical LUT counts. Even the LUT6 counts alone exceed
the actual 35T's 20,800 LUT sites. The actual device has 50 BRAM36 blocks and 90
DSP48E1 blocks. See [AMD's resource table](https://www.amd.com/en/products/adaptive-socs-and-fpgas/fpga/artix-7.html).

The scan-fixture launch/capture FF counts are respectively 916/1362 for core12,
1048/1754 for core16, 321/745 for the cache, and 344/542 for tile16. Fixture
registers and capture muxes are included. The fixture keeps all module inputs
variable and outputs observable; it does not stand in for arithmetic or DDR.

## What the tools identified

The 12-lane core infers 57 of its 59 DSPs from dynamic bank-index expressions;
the other two implement small address/length products. These are not FP32 MACs.
Source-tag counts in the mapped netlist identify `vroom_dense_tile.v` lines 177,
197, 218, 220 and `vroom_tile_buffer.v` line 70. The signed `integer` indices,
scaling, and variable part-selects produce far more logic than the intended
small bank selectors. Bounded unsigned addresses and bank-local selection are
the first implementation changes to investigate, with functional checks.

Each 4096×32 cache bank maps to eight RAMB36 blocks, not four. The RTL expresses
one boot-write address and two independent read addresses; the mapper replicates
storage. Sharing a physical port explicitly between boot writes and one read
port is a candidate repair. The earlier 44-block number was a payload estimate,
not achieved resource use.

The tile-buffer critical path begins at registered `read_base[2]`, passes through
address arithmetic and bank selection, distributed RAM, and output selection,
and ends at a DUT response register. nextpnr reports approximately 10.8 ns logic
and 34.0 ns routing (rounded), giving 22.35 MHz. This diagnoses the existing
address path; it is not the timing of an FP32 MAC or a full policy evaluation.

## Device database limitation

Apio's `xc7a35tcsg324.bin` passes its published SHA-256 check, but the bundled
[Project X-Ray mapping](https://github.com/f4pga/prjxray-db/blob/master/artix7/mapping/devices.yaml)
maps `xc7a35t` to `xc7a50t` fabric. nextpnr reports 75 BRAM36 and 120 DSP sites,
rather than the actual device's 50 and 90. Its LUTX site count is also not the
vendor physical-LUT count. Do not quote those percentages as 35T utilization.

The full cores and cache fail even against this larger resource model. Their
resource failure is useful evidence, but the routed single-buffer result is
only an open-backend diagnostic, not validated timing on the 35T's permitted
resource set. No full-core routed Fmax was obtained.

## Reproduction and retained evidence

```sh
python3 hw/arty/synth/run.py --native-tools --cases cache tile16 core12 core16
```

Raw placement run:
`results/arty_openflow/probe-20261009T203950-ueu1frs7`.
Earlier independent synthesis-only run:
`results/arty_openflow/probe-20261009T203154-8tu83lh_`.
Both retain RTL snapshots, generated scan fixtures/XDC, complete logs, netlists,
source hashes, git/submodule state, seeds, tool identity, and completion status.
Use `summarize.py` for machine-readable diagnostics, a readable report, and
resource figures in a new directory. The earlier synthesis-only runner's
`dut_mapped_cells` field counts only retained name prefixes and must not be used
as DUT area; the later runner removes that field.

There is no FPGA programming, checkpoint export, or motor execution. FP32
operators, nonlinear functions, DDR/CDC, resident W0/W2, cache routing and the
controller adapter are absent. These findings reject the current mapping;
they do not prove that an optimized FP32 implementation is impossible.
